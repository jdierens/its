# Items, taxonomies, photos, and labels

Create an item from **New item**. **Main** and **Trade compliance** sit above the taxonomy fields. Item type is Product, Kit/Package, Service, or Non-inventory, and starts as Product. Service and Non-inventory items should not track stock quantity or need labels. A kit or package may later have components. Mapping these to QuickBooks Inventory, Group/Bundle, Service, and NonInventory comes later. Manufacturer is a controlled list: type to search, pick a close match or an alias, or add a name that is not already there. Model, part number, OEM name, OEM part number, and product page are text. OEM name, OEM part number, and the product page start empty. The product page must be an http or https URL, and a valid address opens in a new tab. Unit is required and starts as Piece. The choices are Piece and Lbs, and an admin can add more by inserting a row in `units`. Condition is New or Used and starts as Used. A new item's condition note is Factory Sealed, New Open Box, or empty. A used item's note is optional free text. ECCN starts as `5A992.C`. US HTS is digits with optional dots, up to 10 digits. CCATS is optional. COO is the country of origin, an ISO alpha-3 code, and starts empty. There is no default country. Hover the COO label to see the full name.

**Admin > Manufacturers** lists those names. The toolbar Save adds a new name and renames any name that differs from the saved one. Add or remove aliases, or merge two, from the card. Merge moves the items and keeps the other name as an alias. Lookup trims the text, ignores case, and collapses spaces, so `SK Hynix` and `SK hynix` are the same name. `Hynix` is a separate alias.

The items table puts Taxonomy between the photo and the SKU. Click a column heading to sort the whole filtered list, not only the rows on the page. Click the same heading again to reverse the order. The active column shows an arrow. SKU, quantity, prices, and numeric attribute columns sort as numbers. Other columns sort by their text, ignoring case. Empty values stay last in either direction. The Edited column sorts by the time. The sort and the page are in the address (`sort`, `dir`, and `page`), so a refresh or the back button keeps them. The default is SKU ascending, one hundred rows at a time. Search and the taxonomy, condition, item type, and manufacturer filters apply before the sort. Previous and Next move through that sorted result. Item type follows the name, then Manufacturer, Model, Part number, OEM name, OEM part number, Product page, Unit, and Condition. Filter the table by taxonomy, condition, item type, and manufacturer. Search matches the manufacturer name, its aliases, OEM name, OEM part number, and product page. Cells for item type, manufacturer, model, part number, OEM name, OEM part number, product page, unit, condition, condition note, ECCN, US HTS, CCATS, country of origin, prices, and the taxonomy's attribute columns edit in place. Enter, double-click, or typing starts an edit. Enter and Tab save and move to the next cell. Esc cancels. SKU and taxonomy do not edit in the table. Each save checks `updated_at` and reloads the row if someone else changed it. The Edited column shows that time. Selecting rows can set condition, item type, country of origin, or ECCN on all of them after a confirmation. Item, contact, taxonomy field, manufacturer, and integration pages keep Save and the other actions in a toolbar that stays on screen while the page scrolls. Save stays grey until something differs from the loaded values, shows a dot while those edits are unsaved, and Ctrl or Cmd+S saves. Undoing the edits greys it out again. Leaving the page asks you to confirm. On an item, Change taxonomy shows which shared fields keep their values, which saved values would be removed, and which fields the new taxonomy adds. Required fields are marked. Lost values can be copied into the item notes. A SKU that contains the current short code can stay as it is, which is the default, or take the new short code. The 90×29 mm label has no spare line for a part number. Admin > Settings chooses Barcode (current), the default, or QR code.

**Export** on the items page offers Google Sheet and CSV download. Current view uses the taxonomy filter and the search, and also condition, manufacturer, and item type when those are set. It exports every matching item, not only the rows on screen. All items ignores the filters. Columns are SKU, taxonomy, item type, manufacturer, model, part number, OEM name, OEM part number, product page, unit, condition, condition note, ECCN, US HTS, CCATS, COO, then ecommerce price, market price, MSRP, and pricing checked when those columns exist, then the primary image URL, created, updated, and one column per attribute name across the exported taxonomies. The primary image link opens the current first photo. CSV downloads without Google. Until both Google env vars are set, the Google option says Not configured and links to the setup notes.

The taxonomy field lists existing taxonomies in `sort_order` and accepts a new name. A new name is created when you save, matched without regard to case, and needs a long code (like `CRD/NIC`) and a 3-character short code (like `NIC`). Both are uppercased as you type and stored in uppercase. The new taxonomy is placed at the end of the order. On the selected taxonomy you can add an attribute (name, integer/decimal/text, optional unit, and whether it uses an allowed-value list).

**Taxonomies & Fields** opens `/taxonomies`. **New taxonomy** asks for a name, a long code, and a 3-character short code, and can start by linking fields that already exist on another taxonomy. Those fields stay one shared definition. Drag a row, or use Up and Down, to change `sort_order`. That order saves on its own and is what the item form lists. **Save changes** appears only after the name or a code is edited. Enter saves that row, and Escape puts the saved name and codes back. A taxonomy with no items can be deleted. Deleting it unlinks its fields and does not delete the field definitions.

**Fields** on a taxonomy lists the shared fields it uses, in `taxonomy_attributes.sort_order`. That order is what the item form and the items table use. **New field** creates a definition and links it. **Add existing field** links definitions that other taxonomies already use, including every field from one taxonomy. A field used by more than one taxonomy shows who else uses it. Editing its name, unit, label, or value list changes it everywhere it is linked. **Required on this taxonomy** marks that link only, so a shared field can be required in one place and optional in another. **Remove from this taxonomy** unlinks it here and is blocked while items in this taxonomy still have a value. The definition can be deleted only when no taxonomy links it and no item value remains. **Merge fields** folds one field into another of the same type: item values and links move, and the extra definition is deleted. Merge stops when one item has a value for both. A type change is blocked while any item uses the field.

Deleting an item asks for confirmation, then removes the item, its attribute values, and its photos, including the files in storage. The original row is not left behind.

Attribute fields with a list accept a listed value or a new one. Integer and decimal values are checked before save. A new value is written into `attribute_values` in the same `create_item` or `update_item` call. Numeric lists are ordered by number.

Photos upload to the private `item-images` bucket. On an existing item they save immediately, at the end of the gallery. On a new item they upload after the item row is created, in the order shown. The first photo is the primary image. The items table uses that photo as the thumbnail. The label does not print a photo.

Click a saved photo, or focus it and press Enter, to open the editor. Delete is the corner icon and asks before removing the file. Drag photos to reorder them, or focus a photo and press the left or right arrow. That order saves immediately. The first photo is primary. `is_primary` stays on the table and a trigger sets it from that order, because the deployed app still reads the column. A later migration drops it after this release is live.

The editor adjusts brightness, contrast, white balance, and sharpness, with a before/after toggle. Crop includes a free rectangle and a 1:1 square, and the photo can rotate 90 degrees. Remove background runs in the browser with `@imgly/background-removal` (the smaller `isnet_quint8` model) and can leave white or transparency. Redact drags a rectangle that is pixelated, or filled solid when the area is small, into the pixels. Saving adds a new gallery photo just after the one you edited and does not replace the original. `source_image_id` records which photo it came from. A white background exports as JPEG at quality 0.92, keeping the edited size and at least 1600 px on the long side when the photo is that large. A transparent background exports as PNG.

**Print labels** opens `/labels`. Look up an item by SKU or uuid, enter the quantity to print and how many copies (default 1), then print. The quantity is only printed on the label. It does not change the item's stock. The item toolbar has a barcode icon, **Print label**, that opens this page with the item filled in. If the item has unsaved changes, it asks you to save first.

The label is one 90 mm × 29 mm landscape page, for a Brother QL-820NWB with DK-1201 (29 × 90 mm) die-cut labels. The item name stays on one line. Names longer than 60 characters are cut to 60 and end with an ellipsis. The font shrinks so a name of up to 60 characters fits the label width. The barcode is Code 128 from [JsBarcode](https://github.com/lindell/JsBarcode), encoding the SKU, or the item id when the SKU is empty. That same value is printed in bold under the bars, about 3 to 4 mm cap height when the code is short. Bars stay at least 8 mm tall and a whole number of 300 dpi dots (4 dots wide, or 3 if the code is long). The quantity number in the middle is about 8.4 mm and bold, with a small QTY caption under it. That caption, the item ID, and the print date share one baseline. The barcode, quantity number, and taxonomy short code share one top line. The short code stays large and bold, and the date is spaced to the same width so their edges line up. An item with no taxonomy leaves that spot empty. The QL-820NWB prints about 25.9 mm of the 29 mm tape, so the label keeps the QTY caption and the date above that edge. Every line is solid black.

**Admin > Settings** has a **Labels** section. **Item** chooses the template. **Barcode (current)** is the default. **QR code** prints the same 90 mm × 29 mm page. Pallet, Crate, Box, and Rack location are listed there for later. The symbol sits on the left with the SKU centered under it. The name wraps onto two lines. Quantity and the taxonomy short code are large, with QTY and the date underneath, and a gap between those captions and the numbers. The description is not printed. The QR code opens the item page on the address of the app you are printing from (`/items/<id>?sku=<sku>`). Error correction is M, each module is 0.423 mm, and the quiet zone stays intact. The version is chosen from that address, so it is not fixed. Print label on the item stays one icon; it does not pick a template of its own.

From a Mac browser, use these print-dialog settings:

- Paper size: 29 × 90 mm
- Orientation: Landscape
- Scale: 100%
- Margins: None
- Headers and footers: off
