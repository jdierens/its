# Picking

Warehouse → Picking lists approved orders that have a product or kit line, and shipped orders that still have no finished pick. The list and the pick ticket header show Order reference, the same column as the sales order list. That value is the eBay order id when the order has one, and otherwise the customer PO. The stored internal reference is not shown. Apply `supabase/migrations/20261029020000_pick_order_reference.sql` by hand so the eBay order id is on the pick payload. Deploying does not run it. Until that file is applied, the reference falls back to the customer PO. Opening an order starts the pick sheet. Opening it does not create a warehouse bin and does not take a number from the bin counter.

Until someone scans a bin, staging is the label `staging bin SO27767` for sales order 27767. That label is tied to the sales order number. It is not a bin such as `20018-B`. A pick still leaves the stock bin. Scan an existing bin, for example `20111-B`, and choose Use bin to put the pick in that bin. A code that is not already a bin is refused. Apply `supabase/migrations/20261028183000_pick_staging_choice.sql` by hand. Deploying does not run it.

The sheet is a table. Each stock line is a group. The item row is SKU, name, ordered, picked, and pending. Under that row, the bin titles are Bin, location, QOH, pick qty, and action, then one row for each bin. Picked lines up with pick qty. Pending lines up with the Pick button. Another bin for that SKU is another row under the same titles. Project and ownership are not on this page. Print ticket prints the pickable lines without the scan boxes and buttons. The ticket is US Letter, landscape, so those columns keep their width. A ticket longer than one page is numbered `1 of 2`. A single page is not. See [Print forms](print-forms.md).

Freight, fees, services, and any line that is not picked are left off the page. That includes service item 4343 (`SER\FREIGHT-OUT`). They are not listed under Not picked.

A bin is about seven characters, such as `20000-B`, and a location is a short code such as `HWS.00.00.00`. Those values, quantities, and the other short codes on the picking list, the sheet, and the serial table stay on one line. The table scrolls sideways instead of breaking a code after one extra character.

A kit component swap stays on the sales-order kit line. A product line can fulfill a different SKU: `item_id` stays the planned SKU and `actual_item_id` is the one that ships. Stock, stock units, and the pick move that fulfilled SKU. Approval can set it. Picking can change it only when Admin > Settings has Allow replacement SKU during pick on. That setting is off until an admin turns it on. An eBay line for `106683` can ship `107021`. The sheet shows the fulfilled SKU and the planned SKU under it. Apply `supabase/migrations/20261028073000_so_sku_replacement.sql` by hand. Deploying does not run it.

Scan a bin code in the scan box to pick the first open line that holds it. Scan or paste serial numbers on their own, with no bin and no line chosen. Each known serial is looked up in stock, the item and the bin it is in are filled in, and that pull is recorded. Paste a Google Sheets column into the scan box the same way as into a line. A serial that is not in inventory does not fill a location by itself. The sheet asks first, and the question includes how many of the entered serials are unknown, such as `2/5 unknown serial numbers`. Yes adds those serials as Pulled and logs them on the pick. Pulled is the same place a pick already goes: issued on the pick while staging is still the order label, or the staging bin when one is assigned and can take the piece. No leaves the unknown serials out. Apply `supabase/migrations/20261029170000_pick_unknown_serials.sql` by hand. Deploying does not run it.

Pasting a spreadsheet range into a line’s serial field adds each serial the same way as Add. A Google Sheets column is one serial per line (`V8H8GBDR`, then `V8HD2PXR`, and so on), including a Windows line break. A row is separated by tabs. Blank cells are dropped. The column is applied together. A known unit is pulled from the bin it is in, including a quantity of one when that bin has not been picked yet. Unknown serials in the column wait for the same yes or no as a single unknown serial. The sheet says how many were accepted and lists the ones that were not, with the reason: already on the item, a different item, or the pick already has a serial for every piece. One failure does not discard the rest of the column. One serial, typed or pasted into the line, still waits for Enter, which only fills the pull-from bin. Add still records that one serial.

Serials already on the sheet, and serials typed while receiving a small quantity, are rows in a table: one line per serial, with the country of origin and, on a pick, the bin it came from. Country of origin is the same country list as the item page. Typing a name such as India, or choosing a row, stores the alpha-3 code, such as IND. After a serial is added, that code stays in the entry row for the next serial until it is changed. From on the entry row is that bin. It fills from the bin picked in the table above, or from a serial lookup when Enter finds the unit in a bin. It is not a second place to choose a bin. The + control adds the serial onto the pick that still has room for it, and says so on that table when it cannot. An unknown serial on a pick that already has a quantity is recorded on that pick. It does not wait for a second confirmation.

Remove and Add actions on the sheet are a trash icon and a plus icon. The name is the button’s tooltip and accessible label.

Finish is the save icon at the top of the sheet, in the same sticky bar as a quote request. The hint says Unsaved changes while the pick can be finished, Saving… while that finish is running, and All changes saved when the list is already finished or still cannot be finished. Until the pick can be finished, the icon is the same faded primary fill as a disabled sales-order action. Its name is Finish pick. Ctrl or Cmd+S finishes when the icon is enabled. Finishing still closes the list the same way: each stock line is fully picked, or the short is acknowledged. That leaves the sales order on picking. The sheet links to packing. Opening packing sets the order to packing. Warehouse → Packing is written up in [Packing](packing.md).

Finish does not lock the sheet. Bins, quantities, shorts, and serials can still be corrected while the order is approved, picking, shipped, or partially shipped. A correction that leaves a line short, or over, reopens the pick list so it is not treated as finished. A correction that stays in balance leaves the list finished. Packing, packed, invoiced, closed, and cancelled stay read-only. The sheet says when the quantities are out of balance. Apply `supabase/migrations/20261104061116_pick_edit_after_finish.sql` by hand after `supabase/migrations/20261104183000_pick_shipped_orders.sql`. Deploying does not run it. Until that file is applied, a finished list still refuses the save and the sheet names the file.

An order that already shipped without a warehouse pick stays shipped. Status `shipped` or `partially_shipped` can open this sheet. Bins, quantities, shorts, and serials are recorded the same way as a pick that has not shipped: the quantity leaves the stock bin, and it is issued on the staging label or moved into a scanned staging bin. Finish closes the pick list. It does not change the sales order status, the ship date, or the shipment rows. The sheet says the order stays shipped. Cancelled, invoiced, and closed orders are not opened for a new pick. The sales order stage control opens the sheet, and Warehouse → Picking lists the order until the pick is finished. Apply `supabase/migrations/20261104183000_pick_shipped_orders.sql` by hand after `supabase/migrations/20261102143000_pack_shipped_orders.sql`. Deploying does not run it.

Beside the sales order number is the same stage control as the sales order and the pack sheet. It goes back to the order, and on to packing once this pick is finished. Opening this sheet after packing, invoicing, or cancellation shows the pick and does not start it again. A shipped order that never had a pick starts one and stays shipped.
