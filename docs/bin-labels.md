# Bin labels

**Bin labels** is under Warehouse (`/warehouse/bins`). A reference is a shared number plus a type letter: `20000-P` pallet, `20001-B` box, `20002-C` crate. The number starts at 20000 because existing physical labels are in the 1xxxx range. **Print next** reserves that many numbers and prints one label each. **Print a sequence** prints a from-to range, creates any missing bins, and moves the counter forward when the range reaches the next number. It does not move the counter backward. **Reprint** prints one or more copies of an existing reference, including a typed 1xxxx label, and does not move the counter. A legacy reference below the counter is stored the first time it is reprinted. A reference that has not been reserved yet is refused, so the counter cannot hand out a duplicate. Each type has its own template choice in Admin > Settings. The page size stays 90 mm × 29 mm. The barcode template matches the physical label: a Code 128 barcode of the reference on top, centered and spanning most of the width, then one line of text. DDS is left-aligned to the bars and the reference, such as `10041-C`, is right-aligned to the bars. The words BOX, CRATE, and PALLET are not printed. The QR template encodes that same reference, not an item URL, with DDS and the reference beside it. The page shows the next number, the last used number, and recent bins. Created by and location are columns on that list and stay blank until Google sign-in and a locations table exist. The print desk does not ask for a name.

**Admin > Settings** keeps the pricing window and the item label template, and adds pallet, crate, and box templates plus **Next bin number**. Pallet, crate, and box each start as DDS + barcode. The next bin number starts at 20000. Saving a next number at or below the highest issued number is refused, and nothing else on the form is saved when the pricing window or the next number is invalid. Rack location stays listed as coming soon.

`bins` stores each bin: the shared number, type (`P`, `C`, or `B`), reference (`20000-P`), optional notes, print count, `created_at`, nullable `created_by`, and nullable `current_location_id`. `created_by` has no foreign key yet. It will reference users once Google sign-in exists, and it stays null until then. `current_location_id` has no foreign key yet. It will reference a locations table later. A parent bin can be added later. `bin_counter` is the single next number. `reserve_bins`, `print_bin_range`, `reprint_bin`, and `set_bin_next_number` lock that row with `select … for update`, then insert bins and move the counter in the same transaction. A rolled-back print does not consume numbers, and two staff printing at once queue on that lock, so a race cannot skip or duplicate a number. A sequence that jumps past the counter does leave a gap on purpose, and the counter moves to one past the end of that range. `bin_events` records created, printed, reprinted, and moved, with a timestamp, an actor, and from/to location ids (no foreign key yet) so a move can be logged later. Row level security stays off on these tables, matching `items`.
