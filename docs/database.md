# Database

Migrations live in `supabase/migrations`. Deploying this repo does not apply them. They are already applied on project `fxsbpreasbdalwthyzvk`. On a new database, run them in order in the SQL editor.

`items.updated_at` is set on each update. Rows that already existed start equal to `created_at`. The export includes that timestamp. Adding that column does not change the item save functions the deployed app already calls. `update_item_cell` writes one table cell and refuses the write when `updated_at` no longer matches. The deployed app does not call `update_item_cell`. `items.item_type` is Product, Kit/Package, Service, or Non-inventory. It is required and defaults to Product, so rows that already existed are Product without a separate update. Service and Non-inventory items should not track stock quantity or need labels. Kit/Package may later have components. A later change can map them to QuickBooks Inventory, Group/Bundle, Service, and NonInventory. `create_item` and `update_item` gain one optional item-type argument at the end, replaced in the same migration so PostgREST still sees a single function. Leaving it out creates a Product and leaves an existing item's type unchanged. `units` is the unit pick list, seeded with Piece and Lbs. Add a row to offer another unit. `items.unit` stores that name, is required, defaults to Piece, and references `units.name` so a rename follows the items. Existing items are Piece from that default. `items.oem_name` and `items.oem_part_number` are optional text. The same two functions take those three values as optional arguments after item type. Leaving them out leaves OEM empty on create and does not change a stored OEM or unit on update. An empty string clears OEM. An unknown unit is rejected. A blank required unit becomes Piece. `update_item_cell` edits the three columns. Taxonomy CBL is named Cable. Motherboard (MBD), Heatsink (SNK), and Unsorted (UNS) are sort orders 11, 12, and 13, after Processor at 10. `items.notes` stores free-form notes. `taxonomy_attributes.required` marks a field as required for that taxonomy only. `change_item_taxonomy` moves an item onto another taxonomy, deletes attribute values the new taxonomy does not link, and can append the removed values to notes. `item_taxonomy_changes` records the old and new taxonomy and the removed values. The deployed app does not call that function.

`attribute_values` holds the allowed values. `attributes.uses_list` turns that list on. `taxonomies.long_code` and `taxonomies.short_code` are unique and nullable. A trigger uppercases them, and check constraints keep `long_code` equal to `upper(long_code)` and `short_code` matching `^[A-Z0-9]{3}$`. `taxonomies.sort_order` is the list order. `item_images` points at files in the `item-images` bucket (`<item_id>/<image_id>.<ext>`). `sort_order` is the gallery order, backfilled from `created_at`. The lowest `sort_order` is the primary photo. `is_primary` is still present and a statement trigger keeps it equal to that first photo, so the currently deployed app can keep selecting it. Dropping the column waits until this release is deployed. The bucket is private, with a 10 MB limit and JPEG, PNG, WebP, and GIF only.

A migration that is applied to the live database before its pull request is merged has to keep working with the app that is already deployed. That means adding columns, tables, and functions only. Do not drop or rename columns, and do not leave two overloads of a function PostgREST already calls. An extra optional argument at the end, applied by replacing the function in one migration, stays compatible when omitting it keeps the old behavior. Do not change that behavior until a later migration after the new code is live.

Storage policies on `storage.objects`, for `anon` and `authenticated`, bucket `item-images` only:

- `item_images_read` (select): authenticated download, object info, and signed URLs. Listing the bucket is not allowed.
- `item_images_insert` (insert): upload.
- `item_images_delete` (delete): remove a file.

There is no update policy, so objects cannot be overwritten. Deleting a photo removes the file through the Storage API and then deletes the `item_images` row. Storage does not allow deleting `storage.objects` from a database trigger.

Row level security is disabled on `items`, `taxonomies`, `attributes`, `item_attributes`, `attribute_values`, `item_images`, `item_taxonomy_changes`, `customers`, `vendors`, `qbo_sync_log`, `ebay_sync_log`, `countries`, `manufacturers`, `manufacturer_aliases`, `price_quotes`, `item_transactions`, `app_settings`, and `units`. The anon key can read and write those rows. This app does not turn RLS on for them. Enabling it without policies would block the client, and the app has no login. `countries` is the ISO 3166-1 list. Manufacturer names and aliases are unique after the same trim, case, and space normalization used by the form. `ebay_sync_log` messages must not include tokens or buyer personal data.

`qbo_connection`, `qbo_sync_cursor`, and `ebay_connection` are the exceptions. Row level security is enabled and there are no policies for `anon` or `authenticated`. Their grants are revoked. Only the service role, from server route handlers, can read them. `qbo_connection` and `ebay_connection` hold the tokens. `needs_reconnect` is set when the refresh token can no longer be used. `qbo_sync_cursor` holds each QuickBooks entity's change cursor and last sync time.

`npm run typecheck` and `npm run build` both need to pass.
